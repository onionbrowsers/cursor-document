# 合并远程分支到当前开发分支

拉取指定远程分支的最新代码，并合并到当前所在的开发分支，全程提供状态提示与异常处理。

**用法**：

- `/git-merge <分支名>`：将指定分支的最新代码合并到当前分支，例如：`/git-merge release-610`
- `/git-merge <分支名> --no-push`：合并后不执行 push，仅在本地完成合并

> ⚠️ **必须提供分支名**，否则立即提示用户补充后重试，不执行任何 git 操作。

**执行步骤**：

1. **参数校验**：解析用户输入，提取 `目标分支名`（必填）和可选的 `--no-push` 标记；若未提供分支名，立即提示用户补充后重试，终止执行。

2. **记录当前分支**：
   - 运行 `git branch --show-current` 获取当前分支名，记为 `CURRENT_BRANCH`
   - 若处于 detached HEAD 状态（输出为空），提示用户切换到具名分支后重试，终止执行
   - 若 `CURRENT_BRANCH` 与用户提供的目标分支名相同，提示"当前已在该分支，无需合并"，终止执行

3. **检查工作区状态**：
   - 运行 `git status --porcelain` 检查是否有未提交的变更
   - 若存在**未暂存或未提交的文件**，终止执行并提示用户：
     - 先执行 `/git-commit` 提交变更，或
     - 执行 `git stash` 暂存变更后再合并
   - 若工作区干净，继续执行

4. **验证目标分支存在**：
   - 运行 `git fetch origin <目标分支>` 尝试拉取远程分支
   - 若 fetch 失败（分支不存在），提示用户检查分支名是否正确，终止执行

5. **切换到目标分支并拉取最新代码**：
   - 运行 `git checkout <目标分支>`
     - 若本地不存在该分支，自动使用 `git checkout -b <目标分支> origin/<目标分支>` 创建并跟踪
   - 运行 `git pull origin <目标分支>` 拉取最新远程代码
   - 若 pull 失败，输出错误详情，切换回 `CURRENT_BRANCH`，终止执行

6. **切换回开发分支**：
   - 运行 `git checkout <CURRENT_BRANCH>`
   - 若切换失败，输出错误详情，终止执行

7. **执行合并**：
   - 运行 `git merge <目标分支> --no-ff -m "Merge branch '<目标分支>' into <CURRENT_BRANCH>"`
   - **合并结果判断**：
     - ✅ **无冲突**：合并成功，继续步骤 8
     - ⚠️ **有冲突**（**禁止 AI 自动解决冲突**）：
       1. 运行 `git diff --name-only --diff-filter=U` 记录冲突文件列表
       2. 立即运行 `git merge --abort` 中止合并，恢复合并前状态
       3. 若当前不在 `CURRENT_BRANCH`，再执行 `git checkout <CURRENT_BRANCH>`
       4. 向用户说明：**不得**由 AI 编辑 `<<<<<<<` / `=======` / `>>>>>>>` 或 `git add` 冲突文件来完成合并
       5. 提示用户在本机手动合并（或使用 IDE 合并工具），解决后自行 `git add` + `git commit`，或解决后再次执行 `/git-merge`
       - **终止后续步骤**，不执行 push，不留下半完成 merge 状态

8. **推送到远端**（仅在合并无冲突时执行）：
   - 若用户未指定 `--no-push`：
     - 检查 `CURRENT_BRANCH` 是否有对应远端跟踪分支
     - 若有：运行 `git push`
     - 若无：运行 `git push -u origin <CURRENT_BRANCH>`
   - 若用户指定了 `--no-push`，跳过此步骤并提示"已跳过 push，如需推送请手动执行 `git push`"

9. **输出结果汇总**：
   - 合并的源分支和目标分支
   - 合并方式（merge commit）
   - 是否已推送到远端
   - 如有冲突：列出冲突文件，说明已 `git merge --abort`，并给出手动合并指引

**注意事项**：

- 必须提供目标分支名，缺少时直接报错提示，不进行任何 git 操作
- **工作区有未提交变更时直接终止**，不允许在脏工作区执行合并（避免数据丢失）
- 合并采用 `--no-ff`（非快进模式），保留合并历史，便于追溯
- **出现冲突时一律 `git merge --abort`，由用户手动合并**；AI 不得代为挑选 HEAD/theirs 或拼接冲突块
- 禁止将代码合并到 `main` / `master` 分支，若 `CURRENT_BRANCH` 为这两个分支，需明确提示用户确认后才可继续
- 若 fetch 失败（网络或权限问题），给出明确错误提示，不继续执行
- 所有操作按步骤输出执行结果，每步完成后打印状态，全部完成后输出汇总
